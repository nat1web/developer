Development Log

How Alfred came to life.

Every line of code, every design decision, every architectural choice — built solo.

💡
Phase 1 — Concept

Architecture & Data Modelling

Designed the full data model from scratch — tasks, events, habits, quests, finance, study, cloud-sync store. Chose SwiftUI + Supabase: real-time capable, offline-first by design.

🏗️
Phase 2 — Core

Task Engine & Calendar

Built task management with due dates, do-dates, reminders, and recurring events. Built the calendar view from scratch: month grid, day detail panel, event forms, and external CalDAV sync.

🤖
Phase 3 — AI

Alfred AI Assistant

Integrated the Anthropic Claude API with a custom tool system of 20+ tools: add_task, add_event, log_expense, manage habits, and more. Built streaming chat with interactive questionnaire forms, option chips, and AI-generated project planning.

🎮
Phase 4 — Gamification

RPG System & Quests

Designed and built a complete RPG progression system: XP levelling, daily/weekly/achievement quests, habit streaks, an in-app shop with equippable items, and a social leaderboard.

💳
Phase 5 — Monetisation

StoreKit 2 Subscriptions

Full tiered subscription system using StoreKit 2: Free (lifetime limits), Pro (monthly AI quotas with auto-reset), and Unlimited (no caps). Paywall UI, purchase flows, restore, and entitlement verification.

🗺️
Phase 6 — Location

Travel Time & Smart Reminders

Automatic geocoding via MKLocalSearch when tasks are added. Alfred computes travel time (car, transit, scooter) and proactively warns users when to leave — integrating location intelligence into AI planning.

✨
Phase 7 — Ongoing

Self-Improving AI

Built a self-improvement error logging system: when Alfred makes a mistake, the user can report it, Alfred logs it with type/correction/context, learns from the pattern across sessions, and displays its accuracy score in-app.
